# 正式 P04 日夜转场回归修复

入口为 `/Game/YIXI/Tests/P04/Maps/L_YIXI_P04_StreamingMaster`。以下运行数据来自用户修复前的三次手动 PIE。本轮采用编辑器静态回读与正常 UBT 构建，修复后画面留给用户验收。

## P0-01　日夜灯光

旧 PIE 中，同一 `LevelSequenceActor_0.AnimationPlayer` 三次都到达第 0 帧和第 30 帧。P04 接入时移除了旧名称 `P02_DirectionalLight` 及其组件的正式太阳绑定，并允许 T00 跳过缺失对象。这组绑定仍承担色温、光源角度、间接光、体积散射等轨道。SkyLight 的父绑定也由原来的组件改成了 Actor。

已在正式 Master 的灯光 Sequence Actor 上按 P04 前记录恢复五条实例覆盖，并取消缺绑定时继续执行的例外。恢复后的解析如下。

| 轨道组 | 实际目标 |
| --- | --- |
| P02 太阳父绑定与组件绑定 | `DirectionalLight_0.LightComponent0` |
| YIXI_Seq 太阳及其组件 | `DirectionalLight_0` 与 `LightComponent0`，沿用资产自带绑定 |
| P02 天光父绑定与组件绑定 | `SkyLight_0.SkyLightComponent0` |
| P02 后处理 | `PostProcessVolume_0` |
| 大气、雾及其组件 | `SkyAtmosphere_0`、`ExponentialHeightFog_0` 及各自组件 |

12 项绑定记录均解析到该 Master 内的对象，其中旧太阳有两项组件记录共用同一 GUID。T00 使用一个原有播放器，白天定位到 0 帧，硬切定位到 30 帧，暂停并保持评估状态。Master 和 Night 的后处理体积都有边界，读取优先级分别为 10000 和 0、权重均为 1。预加载期间需要 Night 可见以验证地面碰撞；在本次读取的已加载关卡中，太阳、天光、大气和高度雾都归属 Master。V3 摄影机使用手动景深，曝光选择保留场景设置。原灯光 Sequence 的 Git 内容与美术提交 `394cefbf` 一致。

## P0-02　白天角色提前消失

原流程在稳定特写满 5 秒后先把 Pawn 移到 Night，等骨骼就绪期间仍从白天的摄影机取景。三次旧日志从稳定到硬切分别为 5.644、6.085、5.802 秒。可确认这一段存在角色已经离开、画面仍在白天的窗口。旧日志未记录第 3 秒时身体的可见性，用户观察到的“最后约两秒”不能据此精确定位。

修复后，正常播放满 5 秒、确认灯光和落脚准备就绪后，先保留当前玩家视口实际渲染的最后一帧。收到渲染线程确认后才允许 Mover 移交同一 Pawn。骨骼稳定、玩具挂接、夜景灯光和相机准备完成时，在同一游戏更新中切换视图与音频并释放白天图像。图像仅短暂存在显存。若当前视口无法提供有效图像，移交前终止并恢复操作。该保持机制面向本项目普通单人第三人称视口。

## P0-03　夜晚地下机位与后腰玩具

一轮旧实测中，夜晚地面约 Z = −5588.82，硬切时摄影机 Z = −5683.29，骨盆 Z = −5691.76。约一秒后骨盆回到 Z = −5497.91，玩具仍在 Z = −5697.54。旧判断接受了正在纠正的骨骼姿态，随后每帧把玩具固定回这份错误记录。日志可以证实镜头和玩具在地下。衣物几何本身是否变形，旧日志无法判定。

正式模式现在等待实际腰部挂点与可渲染身体的骨盆进入同一胶囊的躯干范围，且挂点位置和旋转连续稳定。镜头从同一件已挂接玩具的网格中心定位，检查离地、近裁剪、场景遮挡及有物理资产的服装部件。两秒特写期间保持摄影机稳定，玩具随真实挂点运动，持续检查实际相机和主体是否仍在构图内。约 3.5 秒后撤沿用玩家相机管理器，从这台电影相机混合至同一 Pawn 的即时游戏相机。服装物理体与最终渲染衣摆的轮廓可能不同，最终遮挡需看实际画面。
