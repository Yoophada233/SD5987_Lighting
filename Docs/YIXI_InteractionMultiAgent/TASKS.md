## 冻结任务卡

**A-R1-01。** 对照 R1 源码、资产引用和已有验收，确认 E `Started` 只向当前有效目标派发，HUD 只呈现一种提示。实际回归覆盖遮挡、相邻目标、单门防夹、音效重入和 PIE 重启。保留现有单门、Interactor、HUD 和音效 Box。

**B-DD-01。** 用一个 Actor 和一套状态控制两套独立门轴。正反两面共用固定门框中央的 `CenterInteractionAnchor`，继承 [交互规范](INTERFACES.md)。一次 E 同开同关，反向从当前角度继续，检测任一门扇的关闭路径被占用时两扇同时暂停。音效与事件每个接受的动作只各触发一次。新 BP 由主 Agent 绑定原生类，验收独立尺寸、角度、正反面 HUD、通行、双侧防夹和原单门回归。

**C-TOY-01。** 女孩与玩具实现现有 `IYIXIInteractable`。指定实例发出一次请求后才开放拾取。独立玩家组件持有可配置的网格、手部／后腰插槽和逻辑状态。通过完整验证后才变更持有状态。掉落须可被镜头引用，挂接失败保留原状态。未开放的对象退出目标筛选。验证非法顺序、重复拾取、插槽缺失、实际手持、掉落及后腰挂接。

**D-ROCK-01。** 在游戏内按作者设置的起落点和时长播放确定性轨迹。一次请求最多落地一次。落地与实体封路分别通知，角色占据封路体积时延迟启用阻挡。场景 Trigger 以玩家 Pawn 去重并允许协调器查询当前重叠。验证离屏、重复请求、占位、通行和清理。

**E-STORY-01。** 以指定实例的事件推进教室开门、长廊音效、投石封路、女孩请求、拾取、返程袭击、发现、掉落和转场。阶段变化时复查已重叠的触发区。成功掉落后自动发出带请求标识的转场。独立替身确认同 Pawn 后腰挂接，失败恢复交互且不重放已完成的事件。正式地图和 T01 核心资产属于保护范围。

## 放行规则

每项交接给出文件范围、实际结果和已知缺项。技术审核通过后串行构建，资产写入与 PIE 另行核验。问题按 Issue ID 去重，主 Agent 定级并发修复卡。两次针对同一复现的修复仍失败时停止自动分派，重新定位根因。MCP 阻断时只继续独立的源码和构建工作。
